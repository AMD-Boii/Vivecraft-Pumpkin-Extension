Original discovery snapshot

  • The existing Java source combines Vivecraft protocol negotiation, VR pose tracking, configuration, and substantial gameplay changes.
  • Current Pumpkin Rust documentation targets WebAssembly wasm32-wasip2, not a drop-in Bukkit JAR.
  • At inspected Pumpkin revision de9538a177a14a0835a4edd15a88f19982943626, WIT v0.2 exposes player-custom-payload-event and Java-player send-custom-payload.
  • Declarations are evidence of an exposed interface, not runtime validation. Aim correction, crawl physics, fall handling, mob behavior, and feature parity remain unverified.
  • No target server/client pair, supported protocol range, implementation language, or policy on Pumpkin changes has been approved.

Scope gate: Decide migration expectations for config keys, commands, permissions, Java-facing functionality, and Bukkit-only integrations before implementation.

Best first candidate: Vivecraft sessions

It concentrates a real compatibility contract and enables deterministic byte-level tests, while a small Pumpkin transport experiment can validate the first host dependency.

Recommended first implementation slice, subject to approval: one pinned server/client pair → load plugin → receive VERSION → negotiate honestly → exchange pose data → verify two-client pose relay and disconnect cleanup. This is a milestone, not permission to omit remaining features.
